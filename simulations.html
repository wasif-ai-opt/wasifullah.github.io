Simulations

Algorithms,
in motion.

Small, self-contained demonstrations of the methods behind my research — schedule construction, metaheuristics, evolutionary computation and machine, deep and reinforcement learning — Nothing is precomputed: every schedule, gradient step and Q-update below is produced live. Illustrative, not experimental data.

01 · Static scheduling

Building a hybrid flow shop schedule

Hybrid flow shop · 3 stages · 8 jobs · NEH insertion construction

preparing instance… step 0 partial makespan –

In a hybrid flow shop every job passes through the same stages, but each stage has several parallel machines. Before any search can improve a schedule, a constructive heuristic must build one: here jobs are ordered by largest total processing time and inserted, one by one, at the sequence position that minimises the partial makespan — the idea behind the NEH heuristic. The Gantt chart is rebuilt after every insertion, and a new random instance starts once the schedule is complete.

02 · Metaheuristic search

How simulated annealing improves a schedule

Hybrid flow shop · 10 jobs · insertion neighbourhood · geometric cooling

iteration 0 temperature – best makespan – improvement 0%

A metaheuristic searches by repeatedly perturbing a solution — here, by moving one job to another position in the sequence. Simulated annealing accepts improving moves always, and worsening moves with a probability that shrinks as the “temperature” cools: the small dots are accepted worse moves, the escape mechanism that lets the search avoid local optima early on and settle as it cools. The left panel always shows the best schedule found so far. The same search logic powers the teaching-learning-based optimizer in my hybrid flow shop research.

03 · Evolutionary computation

Evolving a population of schedules

Hybrid flow shop · 10 jobs · population 24 · order crossover · swap mutation

generation 0 best makespan – population mean – improvement 0%

Where annealing walks a single trajectory, a genetic algorithm evolves a whole population: each point cloud is one generation of candidate sequences, parents are selected by tournament, combined with order crossover, and occasionally mutated. Watch the population contract as selection concentrates it around good regions of the search space while the best-so-far line keeps stepping down. On the home page, the same evolutionary principle runs one level higher — evolving the dispatching rule itself rather than a single schedule.

04 · Machine learning

Learning to predict job flow time

Supervised regression · 3 shop-floor features · gradient descent

epoch 0 training MSE – test R² –

The simplest learning-based scheduling idea: collect shop-floor data — here processing time, operation count and slack for each job — and fit a model that predicts an outcome such as flow time. The scatter shows held-out jobs the model never trained on: as gradient descent updates the weights, the points drift onto the diagonal and R² climbs. Such surrogates let schedulers evaluate decisions instantly instead of running a full simulation — but a straight-line model can only capture straight-line relationships, which is where deep networks come in.

05 · Deep learning

A small neural network learns the shop

Feed-forward network · 3–8–8–1 · tanh · backpropagation

iteration 0 training loss – test R² –

Same task, harder data: the target now includes interactions between processing time and slack that no linear model can represent. The network on the left is trained live by backpropagation — edges thicken as weights grow, and node brightness shows activations flowing through the network for successive test jobs. Compare the final R² with the linear model above: the hidden layers buy the flexibility that scheduling data usually demands.

06 · Reinforcement learning

Learning to dispatch by trial and error

Dynamic single machine · Q-learning · actions: SPT / EDD / LPT

episode 1 exploration ε – last tardiness –

Reinforcement learning needs no dataset at all — only reward. The agent runs a dynamic single machine; whenever the machine is free it observes the queue (how busy, how urgent) and picks which dispatching rule to fire, then receives a reward that punishes waiting work and tardy jobs. Early on it explores almost randomly (high ε); as episodes pass, the Q-table on the right crystallises — bright-bordered cells are the learned policy — and per-episode tardiness trends down. This is the learning mechanism behind self-learning scheduling, my core research theme.
